Route Reference

Logic, data flow, auth requirements, and gotchas for every route in Spaceful.

Middleware

src/middleware.ts Edge · Runs on every request

Runs before every page and API route (except static assets and /api/stripe/webhook). Handles session refresh, route protection, admin role enforcement, and auth-page redirect for logged-in users.

Protected path groups
/spaces* /onboard* /account* /admin*
Decision tree
1
Refresh session — Supabase SSR client reads cookies, refreshes token if needed, writes updated cookies back to response. This must happen on every request or the session will expire silently.
2
Protected + not logged in → redirect to /login?next=<pathname>. The next param is used by the login page to redirect back after auth.
3
Admin path + logged in → fetch profiles.role (single indexed lookup). If not 'admin' → redirect to /spaces. This is the only middleware DB call.
4
Auth page (/login, /signup) + already logged in → redirect to /spaces. Prevents re-login.
5
All other requests → pass through with updated cookie response.
⚠ Stripe webhook is excluded from middleware via the matcher config. This is intentional — Stripe sends raw POST bodies that must not be interrupted by cookie/session logic. Always keep api/stripe/webhook in the exclusion list.

Auth

/login & /signup Client Component Redirect if authed

PKCE-based auth via Supabase. Signup creates the user in auth.users, which triggers handle_new_user() to insert a profiles row and grant 3 signup credits. Both pages redirect to /spaces (or the ?next= param) on success.

Signup side-effects (DB trigger)
1
INSERT into auth.users (Supabase managed)
2
on_auth_user_created trigger fires handle_new_user()
3
INSERT into profiles with credit_balance = 3. Username defaults to the email prefix if not provided in raw_user_meta_data.
4
INSERT into credit_transactions — signup_gift ledger entry, delta = +3.
GET /auth/callback Route Handler Public

PKCE code exchange. Supabase redirects here after OAuth or magic-link flows with a ?code= param. Calls supabase.auth.exchangeCodeForSession(code), then redirects to ?next= (default /spaces). On failure → /login?error=auth_callback_failed.

App (auth required)

/spaces Server Component Auth required

Dashboard listing all the user's spaces. Redirects to /login if unauthenticated (middleware also handles this). Primary space is pinned first (sorted by is_primary DESC, updated_at DESC).

DB queries
1
Fetch profiles — username, credit_balance, subscription_status
2
Fetch all spaces for this user — id, slug, display_name, design_tokens, content_json, visibility, is_primary, updated_at
  • Space URL is /:username for the primary, /:username/:slug for secondaries.
  • Each card renders a MiniSpace thumbnail driven by the space's mood from design_tokens.
  • A "New space" dashed card always renders last, linking to /spaces/new.
/spaces/new Client Component Auth required

Credit-gated entry point for creating a new space. Shows a credit cost warning and a slug picker if the user has credits; shows a buy-credits CTA if they don't. Clicking "Continue" navigates to /onboard. Also shows 3 free template cards as an alternative path.

⚠ Credit balance is hardcoded (const CREDITS = 14). Needs wiring to a real session/server value. Same for username. The slug picked on this page is also not yet passed through to onboarding.

Space View

/:username Server Component Public (if not private)

Resolves and renders the user's primary space (is_primary = true). Owner sees edit controls; visitors see read-only + reactions.

DB queries (in order)
1
Fetch profiles WHERE username = :username — gets user_id, display_name, credit_balance. 404 if not found.
2
Fetch spaces WHERE user_id = profile.user_id AND is_primary = true. Includes design_tokens, content_json, visibility.
3
If visitor + space is private → render <SpaceView isPrivate /> (lock screen). No template/reaction queries needed.
4
Fetch space_templates WHERE slug = design_tokens.template_id AND is_active = true. Returns the full TemplateSpec JSON. Null if template not found (falls back to BASE_TEMPLATE_SPECS).
5
Fetch reactions for this space. Owner: all reactions. Visitor: only is_visible = true. Ordered by created_at DESC, limit 20.
6
Render <SpaceView> with space, reactions, templateSpec, isOwner, creditBalance.
SpaceView client component
  • All hooks must be called before the early returns (isPrivate, !space). dtRaw and the 4 template-related useState calls use space?.design_tokens so they're safe when space is undefined.
  • Edit mode: toggled via OwnerChrome. All contentEditable regions and goal toggles are only active when editing = isOwner && mode === 'editing'.
  • Template switching: calls switchTemplate server action → updates design_tokens.template_id, clears spec_override, returns new spec. Client state updates optimistically.
  • Autosave: every edit calls commit(patch) → onUpdate(patch) (optimistic UI) + onSave(next) (saveSpaceContent server action). No debounce — save fires on every onBlur.
SpecRenderer render chain
1
Resolve spec: specProp ?? resolveSpec(template_id, spec_override). resolveSpec looks up BASE_TEMPLATE_SPECS[template_id] and deep-merges spec_override over it.
2
Apply CSS vars: palette fields set as --sp-* inline variables on the root div. Card helpers (cardStyle) and section styles reference these vars.
3
Render decoration: look up DECORATIONS[spec.decoration.type] → render the component behind the content.
4
Render header: scene image, botanical/wave/cloud overlays, monogram chip, h1 title, subtitle. All contentEditable when editing.
5
Render sections: spec.layout.sections.map(id => SECTIONS[id]). focus_hero + notepad pair into a 2-column grid when density is not spacious.
/:username/:slug Server Component Public (if not private)

Same render pipeline as /:username but resolves the space by user_id + slug instead of is_primary. Otherwise identical logic. Secondary spaces are not shown in the spaces dashboard unless navigated directly.

Admin (role: admin)

/admin Client Component Admin only

Admin dashboard. Currently renders hardcoded metric cards and canvas charts. Role check is enforced in middleware (fetches profiles.role). The page itself does not re-check role — rely on middleware.

ℹ When connecting real data: signups from profiles.created_at, MRR from Stripe API or a cached table, AI cost from a prompt_log aggregate.
/admin/templates Server + Client Admin only

Template CRUD with live preview. Server component (page.tsx) fetches all rows from space_templates; if the table is empty it falls back to BASE_TEMPLATE_SPECS so the editor is never blank. Renders <TemplateEditor> (client).

TemplateEditor behaviour
  • Left sidebar: list of templates. Click to select. "New" button initialises a draft from BASE_TEMPLATE_SPECS.garden.
  • Middle: form fields (name, slug, description, preview mood, active/featured checkboxes) + a textarea for raw spec JSON. JSON is validated on each keystroke via JSON.parse. Invalid JSON shows a status message.
  • Right: live SpecRenderer preview, always driven by the current draft spec and preview mood. Updates in real time as JSON is edited.
  • Save: POST (new) or PUT (existing) to /api/admin/templates. Response updates local state; no page reload needed.
/admin/moderation Server Component Admin only

Gallery moderation queue. Shows spaces in moderation_items WHERE status = 'pending'. Approve → sets spaces.gallery_status = 'approved' and visibility = 'public'. Reject → records a rejection_reason.

API Routes

POST /api/generate SSE Stream Auth required

Core AI generation endpoint. Streams SSE events while Claude Haiku generates a personalised TemplateSpec + palette. Includes a retry pass and a fallback so the client always receives a done event.

Request body (validated with Zod)
{
  name:        string,           // 1–60 chars
  vibes:       string[],         // max 3
  goal:        string,           // max 120 chars
  mood:        SpaceMood,        // lavender|sand|forest|ocean|rose|midnight
  layout:      'spacious'|'rich',
  template_id: string | undefined // '' or omitted = AI picks via pickTemplate()
}
SSE event types
Event shapeWhen
{ stage, progress }During generation. Stage label advances ~every 180 chars of Claude output.
{ stage: 'done', tokens }After successful Zod parse or retry. tokens is the full engine token payload.
Token resolution logic
1
Claude streams a JSON object matching TokenSchema (mood, layout, decoration, cards, typography, palette, copy fields).
2
Zod parse. If valid → toTokens(data): extracts layout/decoration/cards/typography into spec_override, resolves template_id (user's choice or pickTemplate(mood, vibes)), emits done.
3
Parse failed → single retry: sends Claude's bad output + validation errors back as a correction prompt. Non-streaming call (max_tokens 1024). Zod parse again.
4
Retry also failed → emit fallbackTokens(mood, layout, vibes). Hardcoded mood-based defaults, no AI palette.
5
Network/SDK error → caught in finally, always closes stream. Emits fallback if not yet done.
  • Template hint in prompt: if template_id is provided, the prompt tells Claude to honour that template's decoration type and header style spirit while personalising colours and sections.
  • Model: Claude Haiku 4.5 (claude-haiku-4-5-20251001). Fast and cheap for structured JSON generation.
  • All hex colours are validated as #RRGGBB. Glow must be rgba() with alpha 0.20–0.35. Zod catches deviations.
/api/admin/templates REST Admin only

Full CRUD for the space_templates table. Every method calls requireAdmin() which re-verifies role server-side (not just middleware).

Methods
GET — list all templates POST — create (slug, name, spec required) PUT — update by id DELETE ?id= — delete by id
  • created_by is set to the admin's user.id on POST. Null for system-seeded templates.
  • PUT accepts any subset of columns — no partial-merge logic, Postgres does it. Don't send id in the body for PUT (it's extracted and used as the WHERE clause).
POST /api/reactions Stub — not implemented

Visitor reaction submission. Always returns 501. Schema is defined (Zod: space_id uuid, message 1–140 chars). Implementation needs: rate limit check (3/space/IP/hour, app-layer — not RLS), SHA256 hash of IP + space_id for visitor_ip_hash, insert into reactions with is_visible = false.

POST /api/stripe/webhook Stub — handlers empty

Stripe webhook receiver. Signature verification is implemented and works. The switch handlers are empty stubs. Raw body parsing is required — this is why the route is excluded from middleware (which would mutate the request). Three events need implementing:

Events to handle
EventRequired action
checkout.session.completedCall grant_credits RPC with purchase delta. Map Stripe customer to profiles.stripe_customer_id.
invoice.paidCall grant_credits RPC with p_cap = credits_monthly_cap (subscription rollover ceiling). Update subscription_status = 'active'.
customer.subscription.deletedUpdate subscription_status = 'cancelled', set credits_expiry_at = now() + 90 days.
⚠ Always call grant_credits / deduct_credits via service-role client. Never use the user-context client for credit mutations — it doesn't have permission and would silently fail RLS.

Server Actions

publishSpace(input) Server Action Auth required

Called from the onboarding publish screen. Creates the space and deducts 3 credits atomically. On success, redirects directly (no return value needed by the client).

Flow
1
Verify auth. If no user → redirect('/login?next=/onboard').
2
Fetch profile. If credit_balance < 3 → return { error: 'insufficient_credits' } (no redirect — UI shows modal).
3
Build design_tokens from generatedTokens (AI output) falling back to preset palette. Build content_json with name, subtitle, goal as first goal chip.
4
Derive slug from name (lowercase, hyphens, max 40 chars). Check if this is the user's first space to set is_primary.
5
Call deduct_credits(user_id, 3, 'generation') via service-role client. If it raises → return { error: ... }.
6
INSERT into spaces. If slug collision (code 23505) → append a 4-char random suffix and retry once.
7
Redirect to /:username (primary) or /:username/:slug.
✗ Credit deduction happens before space insert. If the space insert fails after credits are deducted, the user loses 3 credits with no space created. Add a rollback grant_credits call in the error path to fix this.
saveSpaceContent(spaceId, content) Server Action Auth + ownership required

Called on every onBlur event inside SpecRenderer. Verifies ownership before writing. Serialises camelCase SpaceContent back to snake_case DB field names.

Field name mapping (camelCase → DB)
SpaceContent fieldcontent_json key
heroTitlehero_title
heroNoteshero_notes
readingListreading_list
all otherssame name
  • Ownership check: SELECT user_id from spaces, compare to auth.getUser(). Returns { error: 'forbidden' } on mismatch — never throws.
  • Also updates display_name when content.title changes.
  • No debounce — fires on every blur. Fine for now; consider debouncing if AI journaling prompts are added (they update content on a timer).
switchTemplate(spaceId, templateId) Server Action Auth + ownership required

Called from SettingsDrawer when the owner picks a different template. Updates design_tokens.template_id, clears spec_override (so the new template renders cleanly), and returns the new template's spec from the DB.

Spec override clearing
// destructure to drop spec_override, keep everything else
const { spec_override: _drop, ...restTokens } = space.design_tokens ?? {};
const updated = { ...restTokens, template_id: templateId };
  • Returns { ok: true, templateSpec: TemplateSpec | null }. Client updates activeTemplateSpec and activeSpecOverride state immediately.
  • If the new template isn't in space_templates (e.g. it's a base template not yet seeded), templateSpec is null and SpecRenderer falls back to BASE_TEMPLATE_SPECS.
