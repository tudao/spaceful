Server / Client Boundaries

Server Components RSC

[username]/page.tsx
Fetches profile, space, template spec, reactions. Renders SpaceView as child.
spaces/page.tsx
Fetches user's space list and credit balance.
admin/templates/page.tsx
Fetches all templates from DB, passes as props to TemplateEditor.
(admin)/layout.tsx
Re-checks profiles.role — does not rely on middleware alone.
Server Actions
publishSpace, saveSpaceContent, switchTemplate — always re-verify auth + ownership before writing.

Client Components use client

SpaceView
Owns edit mode state, modal state, template switching. All hooks before early returns.
SpecRenderer
Resolves spec, applies CSS vars, renders decoration + sections. All contentEditable regions live here.
onboard/page.tsx
Full wizard state machine. SSE reading. AbortController for cleanup.
TemplateEditor
Spec JSON textarea → live SpecRenderer preview. CRUD via fetch to /api/admin/templates.
Sections & Decorations
All section and decoration components are client-side. Animations, contentEditable, and state live here.

Data Flows

1 — Onboarding → Publish

Browser (Client)
5-step wizard name · vibes · goal · mood · templateId + density
↓ click "Generate my space"
POST /api/generate Opens SSE stream with AbortController
↓ stream reading loop
Stage events arrive { stage, progress } — animated checklist
↓ stage: 'done'
Publish screen genTokens in state · MiniSpace preview
↓ click "It's perfect → Publish"
publishSpace() server action Passes genTokens (includes template_id, spec_override)
↓
Redirect to /:username or insufficient_credits error modal
Server / API
Auth check supabase.auth.getUser() — 401 if missing
↓
Build prompt User inputs + palette hint + template hint if chosen
↓
Stream Claude Haiku 4.5 Emit progress events every ~180 chars
↓
Zod parse → retry once if invalid toTokens() → template_id + spec_override
↓ emit done event
Verify auth + profile credit_balance ≥ 3 else return error
↓
Build design_tokens + content_json Merge AI tokens with fallback palette
↓
deduct_credits RPC (service role) Row lock → check → deduct → log tx
↓
INSERT spaces Retry with suffix on slug collision (23505)
Database
deduct_credits() SELECT profiles FOR UPDATE
UPDATE profiles SET credit_balance
INSERT credit_transactions
↓
INSERT INTO spaces design_tokens · content_json · is_primary

2 — Space Render Chain (/:username)

Browser (Client)
GET /:username Initial HTML request
↓ hydration
SpaceView (client) useState for mode, modals, localContent, activeTemplateSpec
↓
SpecRenderer resolveSpec → CSS vars → decoration → header → sections
↓
DECORATIONS[type] SVG/CSS animated background layer
↓
SECTIONS[id] × n Each section: contentEditable regions, onBlur → commit()
↓ onBlur fires
commit(patch) onUpdate(patch) [optimistic] + onSave(next)
↓
saveSpaceContent(spaceId, content)
Server
[username]/page.tsx Server component — 4 parallel-ish queries
↓
Fetch profile username → user_id, credit_balance
↓
Fetch primary space is_primary = true — 404 if user has none
↓
Fetch template spec space_templates WHERE slug = template_id AND is_active
↓
Fetch reactions Owner: all. Visitor: is_visible=true only
↓ render SpaceView
saveSpaceContent action Verify auth + ownership → UPDATE spaces
Database
SELECT profiles WHERE username = :username
SELECT spaces WHERE user_id AND is_primary
SELECT space_templates WHERE slug = template_id
SELECT reactions ORDER BY created_at DESC LIMIT 20
UPDATE spaces SET content_json, display_name

3 — Credit Deduction (deduct_credits RPC)

Browser (Client)
User triggers credit action e.g. Publish space (3 cr), Regenerate (2 cr)
↓ confirmation modal for ≥1 cr
Calls server action publishSpace() / regenerate action
↓
✓ Action proceeds Space created / theme generated
✗ insufficient_credits Error modal — no space created, no credits lost
Server Action
Verify auth supabase.auth.getUser()
↓
createServiceClient() Elevated privileges — required for RPC
↓
Call deduct_credits RPC svc.rpc('deduct_credits', { p_user_id, p_delta, p_action })
↓
Check result error?.message includes 'insufficient_credits'?
Database (RPC)
SELECT credit_balance FOR UPDATE Row lock prevents concurrent races
↓
Check balance ≥ delta RAISE 'insufficient_credits' if not
↓
UPDATE profiles credit_balance = balance − delta
↓
INSERT credit_transactions delta = −p_delta, balance_after, action_type
↓
RETURN new balance

4 — Content Edit → Autosave

Browser (Client)
Owner edits contentEditable Goal text, notepad, heroTitle, subtitle…
↓ onBlur fires
Section calls onUpdate(patch) e.g. onUpdate({ heroTitle: 'new text' })
↓ SpecRenderer.commit()
onUpdate(patch) setLocalContent(prev → merged) — optimistic
↓ simultaneously
saveSpaceContent(spaceId, fullContent) Calls server action with full SpaceContent
Template switch (SettingsDrawer) Owner picks a different world
↓
switchTemplate(spaceId, templateId) Clears spec_override, sets new template_id
↓ returns templateSpec
setActiveTemplateSpec(spec) SpecRenderer re-renders with new template
Server Action
Verify auth supabase.auth.getUser()
↓
Verify ownership SELECT user_id FROM spaces WHERE id = spaceId
↓
Serialize SpaceContent camelCase → snake_case (heroTitle→hero_title, readingList→reading_list)
↓
UPDATE spaces SET content_json, display_name
Verify auth + ownership
↓
UPDATE spaces.design_tokens Drop spec_override, set template_id
↓
SELECT space_templates Return new spec (or null → fallback)
Database
SELECT spaces WHERE id = spaceId (ownership check)
UPDATE spaces SET content_json = {...}, display_name = title
UPDATE spaces SET design_tokens (new template_id, no override)
SELECT space_templates WHERE slug = templateId AND is_active

5 — Daily Pulse Entry

Browser (Client)
Owner opens space (morning) DailyPulseSection shows morning prompt
↓ types + tabs out
onBlur — textarea savePulseEntry(spaceId, today, 'morning', body)
Streak updates today_logged = true, streak shown
Opens Companion tab GET /api/companion/daily
Loading skeleton shown ~2s while Claude generates
↓ cached response
Daily message + quote displayed Free — no credit deducted
Server
savePulseEntry server action Auth check → upsert daily_pulse_entries
UPSERT daily_pulse_entries ON CONFLICT (space_id, date, period) DO UPDATE
GET /api/pulse Scan entries backwards from yesterday ≤365 rows → streak
GET /api/companion/daily Check companion_daily for (space_id, today)
Cache miss → build context goals + habits + pulse entries + reading list (~600 tokens)
Claude Haiku → message + pgvector quote INSERT companion_daily, return result
Database
UPSERT daily_pulse_entries entry_date, period, body, space_id, user_id
SELECT daily_pulse_entries Ordered by entry_date DESC LIMIT 365
SELECT companion_daily WHERE space_id = $1 AND date = today
SELECT quotes ORDER BY embedding <-> $goal_emb LIMIT 1
INSERT companion_daily message, quote_text, quote_attr cached for the day

6 — Monthly AI Letter (Cron)

Vercel Cron (1st & 2nd)
1st of month — monthly-snapshot cron POST /api/cron/monthly-snapshot
↓ batches 100 spaces
SELECT active spaces WHERE NOT EXISTS snapshot Idempotent — re-run safe
2nd of month — monthly-letter cron POST /api/cron/monthly-letter
↓
Diff current vs previous snapshot goals added/done, habit rate, notepad word count
↓ Claude Haiku
5-sentence personal letter References real diff data — not generic platitudes
Server
INSERT space_snapshots content_json snapshot per active space
UPSERT daily_pulse_entries period = 'ai_letter', body = letter text
Send via Resend MonthlyLetter.tsx email template
Database
INSERT space_snapshots PK (space_id, snapshot_at) prevents duplicates
SELECT space_snapshots × 2 current month + previous month per space
UPSERT daily_pulse_entries Letter visible in Journal tab immediately
